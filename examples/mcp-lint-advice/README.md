# MCP Lint Advice Example

This walkthrough demonstrates the preferred agent workflow: ask the
`coding-ethos` MCP server for lint and policy context instead of invoking
linters directly.

## Why This Matters

Raw lint commands answer only "what did the tool report?" The MCP path answers
the stronger question agents need:

- which managed tool and generated config were used
- which ETHOS principle or policy the finding maps to
- which remediation skill should be loaded
- whether the result should become SARIF, trend data, or policy feedback
- which files and tool capabilities were involved

That extra context keeps Codex, Claude Code, Gemini CLI, and human operators on
the same enforcement path.

## Start The MCP Server

From the `coding-ethos` checkout:

```bash
make build
bin/coding-ethos-run mcp
```

Agents configured by `coding-ethos` should receive this server automatically
through their generated settings. Manual startup is useful for debugging or for
MCP clients that are not yet generated by the repo.

## Useful MCP Calls

Use `tools/list` first to discover the server capability surface. The important
lint and remediation tools are:

- `lint_check`: run managed lint capture or compiled policy lint.
- `lint_advice`: map a diagnostic to ETHOS policy and skill guidance.
- `sarif_remediation_advice`: turn SARIF evidence into focused repair advice.
- `sarif_risk_summary`: summarize severity, files, tools, policies, and skills.
- `sarif_policy_feedback`: identify unmapped or noisy diagnostics.
- `tool_capabilities`: inspect runtime capabilities such as network, Git,
  writable paths, sandbox profile, timeout, memory, CPU, and seccomp metadata.

## Agent Prompt Pattern

Use this prompt shape when delegating lint remediation to an agent:

```text
Use the coding-ethos MCP server before running any raw linter command.
Call lint_check for the relevant scope, then use lint_advice or
sarif_remediation_advice for each actionable diagnostic. Apply structural fixes
only, then rerun the same MCP lint_check path.
```

## Expected Behavior

An agent following this example should:

1. Query MCP instead of guessing the linter command.
2. Receive compact ETHOS and skill guidance.
3. Fix the underlying issue without weakening generated config or policy.
4. Rerun the managed check path.
5. Report the files changed, checks run, and unresolved risks.

This example is deliberately tool-agnostic. The same pattern applies whether
the underlying finding came from Ruff, mypy, pyright, pylint, SQLFluff, Tombi,
Bandit, actionlint, shell analysis, CEL policy, or a SARIF trace.
